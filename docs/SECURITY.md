# 安全注意事项

本文是项目使用和部署的安全操作要求，**不是正式安全审计报告**，
也不表示当前封装已经满足无人值守实盘运行要求。
模块及调用链见 [架构说明](./ARCHITECTURE.md)，具体命令见
[broker 使用说明](../broker/README.md)。

## 1. 凭证和隐私

- 不在源码、Notebook、README、命令参数、Git 提交、日志、截图或聊天中放入
  access token、refresh token、Cookie、注册管理令牌或 PKCE verifier。
- 完整授权回调 URL 含一次性授权码，也应作为敏感信息处理。
  不分享完整 URL；完成授权后注意浏览器历史、剪贴板和终端记录。
- 账户 ID、卡号、资金、持仓、订单和成交记录属于敏感业务信息。
  即使 Token 已隐藏，账户查询输出和异常响应也不应直接公开。
- 排查时优先提供脱敏后的调用参数、错误码和错误说明。
  `FutuAPIError.details` 和异常说明可能含服务器回传信息，分享前仍需检查。
- `repr` 隐藏部分秘密只减少误打印风险，不是加密，也不阻止直接访问字段。
- `.gitignore` 只是减少误提交；不会保护已跟踪文件或清除 Git 历史。
  提交前检查暂存区，不能仅依赖文件名排除规则。

接口使用 OAuth Token，不需要保存富途登录密码或交易密码。
不要为省事将这些密码写入脚本。

## 2. 系统密钥库的保护范围

- 推荐使用 Linux Secret Service，按应用 profile 保存凭证，
  通过交互终端隐藏输入或直接保存授权结果，避免手工复制 Token。
- 现有接入要求默认密钥库已解锁，要求加密的 Secret Service 会话；
  不自动创建主密钥库、解锁、修改密码或退回明文文件。
- **D-Bus 会话加密不等于证明磁盘上的密钥库已安全加密。**
  应使用非空强密码保护密钥库，并结合系统访问控制和磁盘加密。
- 同一登录用户下的其他程序，以及具备足够系统权限的进程，仍可能访问已解锁秘密。
  不在不可信共享账号、容器或远程开发环境中默认启用真实交易凭证。
- 使用普通登录用户运行，不用 `sudo` 启动业务程序。
  自动登录、SSH、cron 或无桌面的 systemd 服务不保证密钥库已解锁或会话总线可用。
- 不把密钥库主密码写入启动脚本，不把密码设为空来换取无人值守。
  无桌面部署使用 GCP Secret Manager：`broker.credentials.get_store` 在
  Secret Service 会话不可用（如 headless GCP 实例）时改用
  `projects/{project}/secrets/finacial-futu-{profile}`，项目 ID 默认取自实例
  metadata server；刷新后的 Token 写为新 secret version。
  该路径需要 `google-auth` 与最小权限的 Secret Manager IAM 角色。

环境变量是传递凭证的方式，不是加密存储。
调试输出、进程环境收集、崩溃转储和监控工具都需要避免采集秘密。

## 3. OAuth 授权

- 仅在可信设备和富途官方授权页面完成登录，不把登录凭证交给本项目代码。
- 注册、生成授权链接和换取 Token 的 `redirect_uri` 必须一致。
- 一次授权必须使用同一个 `AuthorizationSession` 的 `state/code_verifier`；
  不能重新生成后继续处理旧链接的回调。
- 授权码仅能成功使用一次且有有效期，过期后重新授权，不关闭状态校验来绕过错误。
- `localhost` 指浏览器所在电脑。当前手动复制流程不需要开放公网端口或防火墙。
  如果以后增加自动回调服务，应只监听本地回环地址，并验证路径、state 和请求有效性；
  不应为了让回调可达就把端口暴露给公网。
- 授权范围和账户遵循最小权限原则：只查询时不要无故申请交易写权限。
  本地 `dry_run` 不会收回 Token 本身的服务端权限。

## 4. 模拟盘与实盘

- 搭建策略优先使用 `SimTradingClient`，并从模拟账户列表重新核对账户 ID 和市场。
  不复制实盘账户 ID，不把港股账户与美股 `market_id` 混配。
- 两个客户端默认都是 `dry_run=True`：这表示只预览交易请求，
  **不是已经完成云端模拟交易**。
- 模拟提交使用 `SimTradingClient` 的 `dry_run=False`；
  实盘提交还必须显式设置 `allow_live_trading=True`。
- 实盘双开关与模拟路径检查是应用层防误操作保护，不是权限系统，
  不能防止同一进程中恶意代码直接使用 Token 发请求。
- 不自动接受 `OrderConfirmationRequired`，先审阅确认信息和业务风险。
  如果返回网页链接，应核验其来源和目标域名，不能盲目打开任意跳转。
- 获得 `order_id` 只表示请求得到订单标识，不代表已成交。
  必须检查订单状态、成交量、拒绝原因以及持仓变化。

## 5. 订单超时、重试和限额

- **超时或断线不等于订单失败。** 请求可能已到达富途，
  应先查询订单和成交并核对，再决定后续操作。
- 客户端不自动重试；业务层也不能盲目重放下单、改单、撤单或二次确认请求。
  读请求的限流退避也应有明确上限和日志。
- 当前没有订单幂等系统或跨进程去重。多实例调度前必须设计去重、
  订单状态持久化和异常恢复，防止同一信号重复下单。
- 核对数量、限价、整手、最小价差、币种、时区、交易时段、可卖数量和可用资金。
  最大购买力可能包含融资能力，不能当成可用现金。
- 本地校验不代替券商风控。实盘上线前应增加单笔/单日金额、
  持仓集中度、最大亏损、订单频率和紧急停止等控制。
- 模拟成交不能代替真实流动性、滑点、费用和部分成交评估。
  回测权重也不是可直接提交的订单数量。

## 6. Token 刷新和进程并发

- 密钥库客户端刷新后先保存再使用；保存失败时不要绕过错误继续交易。
- 手动创建 `FutuClient` 时，调用方负责持久化，或配置 `on_token_refresh`。
- 同一 profile 不应被多个进程同时刷新；当前没有分布式锁或跨进程协调。
- 客户端非线程安全，不能通过共享实例假定获得交易或凭证的一致性。
- 删除本地凭证不会撤销服务端 Token，退出 Python 也不会撤销授权。

## 7. 部署与更新

- 使用独立 Python 虚拟环境；不要为了富途 HTTP 接口安装不必要的研究或桌面依赖。
- 只从可信来源安装依赖。当前依赖范围不是完整锁定文件，
  生产部署应固定并记录实际版本，审查升级并保留可回滚版本。
- HTTP 使用 HTTPS 和默认证书校验，不关闭 TLS 校验，
  不把凭证发往自建不可信代理。代理、抓包及调试工具也可能接触请求秘密。
- HTTP 层不自动跟随重定向，避免携带认证信息跳转或重放订单；
  不应通过业务层盲目跟随跳转来绕过这一保护。
- 代码更新后重启解释器或业务进程；普通 pip 安装还需重新安装更新后的包，
  避免误以为旧进程已使用新安全保护。
- 不将离线测试通过当成账户权限、服务参数或端到端交易已验证。
  尤其模拟盘数量查询的 `invalid parameter` 根因尚未确认，不应带病上线实盘。

## 8. 凭证泄露或误交易时

1. 停止策略调度和新的订单提交；不要自动补单或反向交易掩盖问题。
2. 在富途官方渠道查询订单、成交和持仓，核对可能已到达服务器的请求。
   可撤订单由用户审阅后处理。
3. 如果怀疑凭证泄露，先在富途侧撤销相关授权或令牌，
   再清理本地密钥库记录、环境变量及其他副本，并重新授权。
4. 若秘密进入 Git 或日志，按泄露处理：仅删除当前文件或改写历史不等于令牌已失效。
5. 保留脱敏的时间、订单标识及错误证据用于核对，不传播原始秘密。

## 9. 每次联调前检查

- [ ] 当前使用的是模拟盘还是实盘，账户和市场已经核对。
- [ ] 当前 `dry_run` 设置符合预期，没有无意开启实盘双开关。
- [ ] 凭证未写入代码、日志、终端命令历史或提交内容。
- [ ] 密钥库及凭证访问权限符合当前运行环境。
- [ ] 请求失败后的查询核对、去重与停止机制已经准备好。
- [ ] 报价、资金、数量、币种和时间单位已核对。
- [ ] 测试结论明确区分离线协议测试与真实服务验证。
